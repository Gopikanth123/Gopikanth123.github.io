# 14. Design System

The site's visual identity should read as an **engineering document, not a marketing
page** — this is a portfolio for someone who designs production systems, so the
design itself should look like it was drawn by a systems architect: precise,
labeled, quietly technical. Avoid the two most common AI-portfolio defaults —
generic dark-navy-plus-neon-gradient hero orbs, and cream-background serif
"studio" portfolios. Neither says anything about *this* subject.

## 14.1 Design Token System

**Color — 6 named tokens:**

| Token | Hex | Use |
|---|---|---|
| **Blueprint** | `#0B0D12` | Base background — near-black, cool, not pure navy |
| **Steel** | `#12151C` | Card / panel surfaces, raised 1 step off Blueprint |
| **Paper** | `#EDEFF4` | Primary text |
| **Fog** | `#8A93A6` | Secondary/muted text, captions, timestamps |
| **Trace** | `#7C8CFF` | Primary accent — active links, the signature trace line, focus states |
| **Beacon** | `#4FD1C5` | Secondary accent, used sparingly — live/success states, metric highlights |

Grid lines and dividers are not a separate hex — they're **Steel at 8–12% opacity
over Blueprint**, so the schematic grid feels etched rather than drawn.

**Typography — 3 roles:**

| Role | Typeface | Where |
|---|---|---|
| **Display** | Space Grotesk | Hero headline, section titles — geometric, technical, slightly unconventional letterforms |
| **Body** | Inter | All body copy, descriptions, nav — optimized for long-form readability |
| **Annotation / Mono** | JetBrains Mono | Eyebrows, tags, tech-stack chips, dates, coordinates, architecture-diagram labels, code |

Type scale (desktop): Hero 64–80px / Section title 36–44px / Card title 20–22px /
Body 16–17px / Mono annotation 12–13px, uppercase, letter-spacing +0.08em.

**Layout concept:**
A persistent, near-invisible schematic grid (4–6% opacity Steel lines) sits behind
every section, reinforcing the "engineering drawing" feel without competing with
content. Content sits on a 12-column grid with wide margins and asymmetric
compositions (text doesn't always center — let it sit off-axis like an annotated
diagram). Section dividers are hairline rules with a mono coordinate label
(`§03 — PROJECTS`) instead of large numbered badges — justified because it mirrors
how real technical documents are actually labeled, not decoration for its own sake.

**Signature element — "Live Trace":**
A single thin animated line in **Trace** color that draws itself through a
node-and-edge path. This is not decoration — it's a literal visualization of what
the work is: a request moving through an agent, a tool, and back. It appears once,
deliberately, in the hero (drawing the User → Agent → Tools → Result path on load),
and reappears at smaller scale inside each project's architecture diagram, drawing
in as that diagram scrolls into view. It is the one bold, repeated motif — everything
else in the design stays quiet so this reads clearly.

## 14.2 Per-Section Design Specs

**Hero**
- Full-bleed Blueprint background with the faint schematic grid.
- Headline in Display type, left-aligned, generous line-height; subheadline in Body
  directly beneath in Fog/Paper.
- The Live Trace diagram renders beside or behind the text — a minimal node graph
  (`User → Agent → Tools → Result`) that draws itself in once on load, then sits
  static. Respect `prefers-reduced-motion`: render it fully drawn, no animation.
- CTAs styled as mono-labeled buttons with directional cues, e.g. `→ VIEW_PROJECTS`,
  `CONTACT_ME`, echoing a CLI/terminal register that matches the subject matter.

**About**
- Two-column asymmetric layout: narrative text on the left (Body type), a compact
  "spec sheet" panel on the right in mono type — `ROLE`, `LOCATION`, `FOCUS`,
  `EXPERIENCE` as labeled rows, like a datasheet, not a bio card.
- No stock photography or abstract AI imagery; if a profile photo is used, keep it
  small, framed with a thin Trace-colored corner bracket, not a full-bleed hero shot.

**What I Build**
- Grid of cards on Steel surfaces with thin corner brackets (⌐⌐-style, in Fog,
  brightening to Trace on hover) instead of drop shadows — echoes the schematic
  language rather than generic elevation.
- Each card: a short mono eyebrow tag, title in Display/medium weight, 1–2 line
  description in Body. On hover, a faint trace line connects to the next related
  card — subtle, off by default with reduced motion.

**Experience**
- Vertical timeline with a single continuous Trace-colored line connecting entries
  — the one place a literal timeline/sequence device is earned, since the content
  really is chronological.
- Each entry: mono date range, role/company in Display, responsibilities in Body
  as a tight bulleted list.

**Projects**
- Each project renders as an expandable card: name, one-line description, mono
  tech-stack chips.
- Where a project includes an architecture diagram (see `project_description.md`),
  render it as a clean SVG schematic — labeled boxes, thin connecting lines, the
  Live Trace motif drawing through the active request path — not as literal ASCII
  text on the live site (ASCII in the markdown source is for portability/authoring;
  the rendered UI should be a proper vector diagram).
- Projects without a listed architecture (e.g. the Smart Glasses research project)
  should **not** get a forced diagram — show description, focus areas, and
  publication details instead. Don't manufacture a diagram where the source
  material doesn't call for one.

**Education / Publications / Certifications**
- Compact datasheet-style rows or a simple table: mono dates/institution codes on
  the left, Body description on the right. Resist turning this into another card
  grid — density and precision suit this content better than decoration.

**Contact**
- Minimal, centered, generous negative space on Blueprint. A single thin
  schematic frame (corner brackets, not a full border) around the block.
  Email/social links styled as mono, underline-on-hover only — no button chrome.

**Footer**
- Quiet: copyright line in Fog, social icons small and monochrome until hover
  (Trace on hover).

## 14.3 Motion, Accessibility & Responsiveness Floor

- **One orchestrated moment** (the hero Live Trace draw-in) plus subtle
  scroll-reveals and hover micro-interactions — nothing more. No competing
  animated gradients, particle fields, or auto-playing loops.
- Respect `prefers-reduced-motion` everywhere: replace draw-in animations with
  their fully-rendered end state.
- Visible keyboard focus states using the Trace color at all interactive elements.
- Maintain WCAG-adequate contrast between Paper/Fog text and the Blueprint/Steel
  surfaces.
- Fully responsive: collapsible nav, stacked project cards, the schematic grid
  and Live Trace diagrams scale down (simplify node count on mobile rather than
  shrinking illegibly) rather than causing horizontal scroll.

**Recommended stack:** React + Next.js + TypeScript + Tailwind CSS (custom tokens
mapped to the palette above), Framer Motion for the Live Trace and scroll-reveals,
Lucide for icons, deployed on Vercel.
